## 三、快速开始（零安装路径，推荐）

本地开发**不需要 Docker，也不需要安装 PostgreSQL**：默认使用 PGlite（编译成 WASM 的 PostgreSQL 18，内置 pgvector 0.8），数据库直接跑在 Node 进程里。

```bash
pnpm install
cp .env.example .env
pnpm setup        # = db:push + db:seed + demo:prepare
pnpm dev:server   # http://localhost:3100/api   （接口文档 /api/docs）
pnpm dev:admin    # http://localhost:5173       （admin / admin123）
```

小程序：微信开发者工具导入 `apps/miniapp` → 详情 → 本地设置 → **勾选「不校验合法域名」**。不需要真实 AppID。

## 四、三条数据库路径（都已实测）

| 路径 | 适用场景 | 前提 | 实测结果 |
|---|---|---|---|
| **PGlite** | 本地开发、买家零安装试用 | 无 | 29 张表、验收 130 项全过 |
| **原生 PostgreSQL** | 本机长期开发 | 需要 pgvector（Windows 要自己编译，见第四节之二） | PostgreSQL 18.6 + pgvector 0.8.6，验收 130 项全过 |
| **Docker** | 交付给买家、服务器临时环境 | 装 Docker Desktop | pgvector/pgvector:pg16（PG 16.15 + pgvector 内置），验收 130 项全过 |

三套用的是同一份 Drizzle schema、同一套迁移 SQL，切换只改 `.env`。

### 路径一：PGlite（零安装，默认）

§§§
DB_DRIVER=pglite
PGLITE_DATA_DIR=.data/pg
§§§

数据落在 `apps/server/.data/pg`，删掉即重置。

### 路径二：原生 PostgreSQL

§§§
DB_DRIVER=postgres
DATABASE_URL=postgres://campus:campus@127.0.0.1:5432/campus_mall
§§§

Windows 上装 pgvector 的完整步骤见「四之二」。

### 路径三：Docker（实测通过）

§§§bash
docker compose up -d postgres
§§§

镜像 `pgvector/pgvector:pg16` **自带 pgvector**，不用编译，容器起来就能用。

**端口冲突**：如果本机已经装了原生 PostgreSQL（默认占用 5432），用环境变量换端口：

§§§powershell
$env:POSTGRES_PORT='5433'
docker compose up -d postgres
# 然后 .env 改成 5433
§§§

#### 国内网络必须配镜像加速

Docker Hub（`registry-1.docker.io`）在国内直连基本拉不动，会卡在：

§§§
failed to resolve reference "docker.io/pgvector/pgvector:pg16":
dial tcp ...:443: connectex: A connection attempt failed because the connected
party did not properly respond after a period of time
§§§

改 `C:\Users\<用户名>\.docker\daemon.json` 加镜像加速（本机实测这几个可用）：

§§§json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1panel.live",
    "https://hub.rat.dev",
    "https://dockerproxy.net"
  ]
}
§§§

改完重启 Docker Desktop，用 `docker info --format '{{range .RegistryConfig.Mirrors}}{{.}} {{end}}'` 确认生效。
本机实测：配好之后 `pgvector/pgvector:pg16` 顺利拉取完成。

#### 启动顺序建议

容器是 `restart: unless-stopped`，Docker Desktop 启动后会自动拉起。
注意 **Docker Desktop 必须先运行**：引擎没起来时 `docker compose` 会报 `dockerDesktopLinuxEngine` 管道不存在。
## 四之二、Windows 原生 PostgreSQL + pgvector（已实测路径）

不想用 Docker 的话，Windows 上也能跑通，但**pgvector 需要自己编译** —— EDB 的 PostgreSQL Windows 安装包不带它。
下面是本机实测成功的完整流程。

### 前置条件

| 依赖 | 说明 |
|---|---|
| PostgreSQL 18 | EDB 安装包即可，装完服务会自动跑在 5432 |
| Visual Studio Build Tools 2022 | **必须勾选「使用 C++ 的桌面开发」工作负载**，提供 nmake / cl / link |
| 管理员权限的终端 | 安装扩展要写 `C:\Program Files\PostgreSQL\18` |

验证编译器在位：

§§§powershell
$p = 'C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Tools\MSVC\<版本>\bin\Hostx64\x64'
Test-Path "$p\nmake.exe"; Test-Path "$p\cl.exe"
& 'C:\Program Files\PostgreSQL\18\bin\pg_config.exe' --version
§§§

### 编译安装 pgvector

GitHub 的 `git clone` 在部分网络下会被重置，改用 codeload 直接下 tar 包更稳：

§§§powershell
$tar = "$env:TEMP\pgvector.tar.gz"
$dst = "$env:TEMP\pgvector-src"
Invoke-WebRequest 'https://codeload.github.com/pgvector/pgvector/tar.gz/refs/heads/master' -OutFile $tar
New-Item -ItemType Directory -Force -Path $dst | Out-Null
tar -xzf $tar -C $dst
§§§

然后写一个 bat（PowerShell 里链式调用 vcvars 容易被引号坑到）：

§§§bat
@echo off
call "C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\VC\Auxiliary\Build\vcvars64.bat" >nul
set "PGROOT=C:\Program Files\PostgreSQL\18"
cd /d "%TEMP%\pgvector-src\pgvector-master"
nmake /F Makefile.win
nmake /F Makefile.win install
§§§

跑完检查产物：

§§§powershell
Test-Path 'C:\Program Files\PostgreSQL\18\lib\vector.dll'
Test-Path 'C:\Program Files\PostgreSQL\18\share\extension\vector.control'
§§§

本机实测装的是 **pgvector 0.8.6**（`vector.dll` 273 KB + 42 个 SQL 升级脚本），与项目 PGlite 环境的向量版本一致。

### 建业务账号、数据库与扩展

`CREATE EXTENSION vector` 需要超级用户，脚本一次性做完（幂等，可重复执行）：

§§§powershell
pwsh -File scripts/init-postgres.ps1 -PostgresPassword '<postgres 超级用户密码>'
§§§

脚本会建 `campus` 角色、`campus_mall` 库、装 vector 扩展，并**用业务账号实际建一张带 vector 列的表再删掉**，确认权限真的够。
超级用户密码只作为参数传入，不写入任何文件。

### 切换项目

§§§bash
# .env
DB_DRIVER=postgres
DATABASE_URL=postgres://campus:campus@127.0.0.1:5432/campus_mall

pnpm db:push && pnpm db:seed && pnpm demo:prepare
pnpm dev:server
§§§

验收结果（PostgreSQL 18.6 + pgvector 0.8.6，实测）：

§§§
vector 列 3 个 / HNSW 索引 3 个 / 29 张表
pnpm test:acceptance  34 项全部通过
pnpm test:miniapp     23 项全部通过
§§§

> **踩过的坑**：`tsx` 直接跑的脚本（db:push / db:seed / ai:embed / demo:prepare）如果只用 `dotenv/config`，
> 只会读 `cwd/.env`，而 monorepo 的 `.env` 在仓库根目录 —— 结果脚本静默落到默认值连了 PGlite，
> 出现「服务连 PG、脚本连 PGlite」的错位。现在脚本统一走 `src/db/env.ts`，按 `cwd/.env` → `仓库根/.env` 顺序查找。

## 七、生产部署

### 后端

```bash
pnpm --filter @campus/server build
NODE_ENV=production node apps/server/dist/main.js
```

建议用 pm2 或 systemd 托管；上传的图片在 `apps/server/uploads`，记得挂持久化卷或用对象存储。

### 管理后台

```bash
pnpm --filter @campus/admin build   # 产物在 apps/admin/dist
```

nginx 示例：

```nginx
server {
  listen 80;
  root /var/www/campus-admin;      # apps/admin/dist
  location / { try_files $uri $uri/ /index.html; }
  location /api/ { proxy_pass http://127.0.0.1:3100/api/; }
  location /uploads/ { proxy_pass http://127.0.0.1:3100/uploads/; }
}
```

### 小程序

小程序是**原生、零 npm 依赖、无构建步骤**的：微信开发者工具直接打开 `apps/miniapp` 就能运行，不需要 `npm install`、不需要「构建 npm」。所以「能不能上传」只取决于下面这些**外部条件**，与代码无关。

#### 只做演示/答辩：不需要任何资质

开发者工具 → 预览 / 真机调试，或者上传后设为**体验版**给同学扫码。这条路只要后端能被手机访问到即可（见下面第 1 条），不需要备案、不需要类目、不需要审核。

#### 正式发布：按顺序过这 5 关

| # | 事项 | 说明 | 卡住会怎样 |
|---|---|---|---|
| 1 | **后端要能被手机访问** | 上传一台服务器跑后端，用 Nginx 反代 `/api/` 与 `/uploads/`（配置见上一节）。手机和电脑不在同一局域网时，`localhost` 是不通的 | 真机打开一片空白 / 请求全失败 |
| 2 | **必须 HTTPS + 域名已备案** | 微信只允许 `https://` 的合法域名，且域名要在工信部备案（国内服务器备案通常 1-3 周）。自签证书不认 | 发布版请求被拦，报「不在以下 request 合法域名列表中」 |
| 3 | **小程序后台配置服务器域名** | 登录 [mp.weixin.qq.com](https://mp.weixin.qq.com) → 开发 → 开发设置 → 服务器域名，把 `https://你的域名` 加进 **request 合法域名**（用到上传图片再加 **uploadFile 合法域名**） | 同上。注意：`urlCheck:false` 只在开发者工具里生效，真机/发布版一律按白名单校验 |
| 4 | **改 `apps/miniapp/config.js` 的 `BASE_URL`** | 把 `const BASE_URL = ENV.dev` 改成 `ENV.prod`，并把 `ENV.prod` 改成你的正式地址（形如 `https://你的域名/api`）。同文件里的 `ASSET_URL` 会自动跟着变，商品图片才能显示 | 请求打到 localhost |
| 5 | **配 `WX_APPID` / `WX_SECRET`** | 在服务器 `.env` 里填自己的小程序 AppID 与密钥。**不填的话后端走开发模式，任何人随便传一个 code 都能登录成新用户** | 用户体系形同虚设 |

AppID 填在 `apps/miniapp/project.config.json` 的 `appid` 字段（当前是 `wx4d5e757cc3836855`，不是你自己的就换掉）。

#### 审核与类目资质（这是真正卡住电商小程序的环节）

代码全部走通之后，还差**微信平台的类目审核**，这一关必须提前准备：

- 卖零食 → 需要选择「食品」相关类目，并提交 **《食品经营许可证》**（或食品小作坊登记证/食品生产许可证）
- 卖二手教材 → 涉及出版物，可能需要 **《出版物经营许可证》**
- 小程序主体如果是个人号，**不能开通微信支付、也不能做食品类目**，必须用企业/个体工商户主体

> 校园项目如果只是答辩或内部试用，用**体验版**就够了，不需要类目与资质。要真正对外卖货，先确认你能拿到上述证照。

#### 其他

- **代码包体积**：主包上限 2MB、总包 20MB（分包）。本项目是原生小程序、没有 npm 依赖，实测离上限很远，不用担心
- **支付**：目前下单/充值是**模拟支付**（余额直接加减）。真实收款需要申请微信支付商户号并接支付回调，代码里 `wallet.recharge` 与 `order.pay` 是预留的接入点
- **上传步骤**：开发者工具点「上传」→ 填版本号与备注 → 在 mp 后台「版本管理」提交审核 → 审核通过后点「发布」

## 八、常见问题

| 问题 | 原因与处理 |
|---|---|
| 小程序请求全失败 | 没勾「不校验合法域名」，或后端没启动 |
| AI 回复是模板话术 | 正常：没配 `LLM_API_KEY` 时的降级行为，`/api/ai/status` 会显示 mock |
| 拍照找同款提示「看不了图」 | 没配 `LLM_VISION_MODEL`；这是刻意设计，会引导用户描述或扫码 |
| 搜索结果不语义 | 没配 `LLM_EMBEDDING_MODEL`，或配了但没跑 `pnpm ai:embed` |
| 想清空数据重来 | `pnpm db:reset`（会重建 29 张表并重新灌演示数据） |
| 端口被占用 | 改 `.env` 的 PORT，同时改 `apps/admin/vite.config.ts` 的代理目标 |
| 迁移报 vector 相关错误 | 建表必须先 `CREATE EXTENSION vector`，用 `pnpm db:push` 而不是 drizzle-kit push |
| Windows 装 PostgreSQL 后没有 vector | EDB 安装包不带 pgvector，需要按第四节之二自己编译 |
| 改了 .env 但脚本还是连 PGlite | 脚本按 `cwd/.env` → `仓库根/.env` 查找，确认改的是被找到的那一份 |
| 移动过项目目录后报 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | pnpm 发现目录变了要重建 node_modules；在项目根执行 `$env:CI='true'; pnpm install` 即可（几秒钟，走本地缓存不联网） |

## 九、二次开发：加一个新的 AI 能力

三步，不需要改 Agent 与前端：

1. 在 `apps/server/src/modules/ai/tools/` 写一个类，实现 `AiTool`（name / description / schema / run）
   - 只读工具直接 `run`；写操作加 `write: true` 并实现 `confirmSummary`，框架会自动走二次确认
   - 想让工具只在某些场景出现，填 `scenes: ['merchant']`
2. 把类注册进 `ToolRegistry` 构造函数
3. 重启后端，`GET /api/ai/status` 的 tools 列表里就会出现它，模型也能直接调用

前端零改动：工具调用过程会通过 `tool_start` / `tool_result` 事件自动展示。
