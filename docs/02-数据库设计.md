# 数据库设计

共 **29 张表**，按业务域分五组。金额一律用「分」存整数，时间统一 timestamptz。

## 用户域

| 表 | 说明 |
|---|---|
| app_user | 用户主表：openid（小程序）/ username+passwordHash（后台）/ 角色 / 余额 |
| user_profile | **AI 长期记忆**：口味画像 taste、忌口 avoidTags、预算、专业年级、aiMemory 自由文本 |
| address | 收货地址，支持校区 + 宿舍楼 |
| user_behavior | 行为埋点：view/search/cart/order/favorite/chat，协同过滤与画像的原料 |

## 商品域

| 表 | 说明 |
|---|---|
| category | 分类，kind 区分 snack / book 两条业务线 |
| product | 商品主表，同时容纳零食属性（flavor/spicyLevel/shelfLifeDays）与二手书属性（isbn/author/publisher/edition/course/condition/hasNotes），带 embedding 向量列 |
| product_sku | 零食按规格；**二手书按具体副本**（库存通常 1，成色与卖家备注各不相同） |
| product_image | 商品图 + 图片向量，拍照找同款的检索底库 |
| tag / product_tag | 标签字典（辣/甜/宿舍必备/考研/有笔记…），让 AI 检索条件结构化可统计 |
| review | 用户评价 |
| review_summary | **AI 生成的评论摘要**：pros / cons / audience / keywords / 评分分布 |

## 交易域

| 表 | 说明 |
|---|---|
| cart_item | 购物车，source 标记是否由 AI 加入 |
| order | 订单，source=ai 的订单单独统计「AI 转化率」，aiConversationId 可回溯到会话 |
| order_item | 订单明细，带商品快照（标题/封面/规格）防止商品改价后信息漂移 |
| payment | 支付流水（校园项目为模拟支付） |
| after_sale | 售后单，source 标记是否由 AI 代提交 |
| wallet_log | 余额流水 |

## AI 域（差异化所在）

| 表 | 说明 |
|---|---|
| ai_conversation | 会话：场景 shopping/support/merchant、页面上下文、滚动摘要 |
| ai_message | 消息：role、正文、商品卡片、token 用量、耗时、degraded 降级标记 |
| ai_tool_call | **工具调用审计**：工具名、入参、返回值、耗时 —— 管理后台可视化回放 |
| ai_pending_action | 写操作待确认：加购/下单/售后，用户确认后才执行 |
| ai_knowledge | RAG 知识库：售后政策、配送说明、辣度说明、预算搭配，带向量 |
| ai_feedback | 回答点赞点踩，用于效果评估 |

## 系统域

sys_menu（后台动态菜单）、sys_config（AI 开关等配置）、login_log、operation_log（管理端与 AI 的写操作都记账）、notification（消息通知）。

## 向量与索引

- 向量维度由 LLM_EMBEDDING_DIM 决定（默认 1024），**改维度要重新生成迁移**（DDL 里写死了 vector(1024)）。
- product / product_image / ai_knowledge 各建 HNSW 余弦索引。
- product 额外建 GIN 全文索引，用于「关键词 + 向量」混合检索：先全文召回，再用向量重排。
