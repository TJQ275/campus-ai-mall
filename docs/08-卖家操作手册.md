# 卖家操作手册

> 面向**不懂技术的卖家**：从零开始把商品上架、把 AI 接上自己的大模型。
> 全程在浏览器里点，不需要改代码、不需要重启服务。

管理后台地址：`http://localhost:5173`（服务器上部署后就是你的域名）
默认账号：`admin` / `admin123` —— **接手后第一件事就是改掉它**，见文末。

---

## 一、每天要做的事：加商品

### 1.1 先建分类（只做一次）

商品必须挂在分类下，所以第一次使用先看一眼分类够不够。

- 零食：辣味 / 膨化 / 饮料 / 速食 …
- 二手书：教材 / 考研 / 外语 / 文学 …

演示数据里已经各建好了几个，够用就不用管。需要新增时，直接改 seed 数据或让技术同学加一个 `POST /api/admin/categories` 的入口即可（分类是低频操作，没有单独做页面）。

### 1.2 新增一件商品（3 分钟）

进「**商品管理**」→ 点右上角「**新增商品**」，按顺序填：

| 字段 | 怎么填 | 注意 |
|---|---|---|
| **品类** | 选「零食」或「二手书」 | 选完下面的字段会跟着变，两类商品字段不一样 |
| **商品标题** | 例：`卫龙大面筋辣条 106g` | 必填。带上规格，AI 和用户都更容易搜到 |
| **副标题** | 一句话卖点 | 显示在商品卡片上，例：`宿舍必备，一包上瘾` |
| **商品图片** | 点「上传图片」选本地图片 | 会自动压缩到 1200px 再上传，手机拍的照片也能用 |
| **所属分类** | 下拉选一个 | 必填，只列出当前品类下的分类 |
| **售价** | 单位**元**，例 `3.50` | 必填。系统内部按「分」存储，填错了不会出现小数误差 |
| **原价** | 划线价，留 0 不显示 | 选填 |
| **库存** | 件数 | 卖二手书时通常填 1（每本都是独立副本） |
| **状态** | 上架在售 / 下架 / 草稿 | 拿不准就先存成「草稿」，确认后再改「上架」 |
| **标签** | 输入后回车，可加多个 | **AI 导购靠标签找货**，见下面 1.3 |
| **商品详情** | 大段描述 | 选填 |

零食还会多出：口味、辣度（0-5 星）、规格、保质期。
二手书还会多出：ISBN、作者、出版社、版次、适用课程、成色、有无笔记。

填完点「保存」，商品立刻上架并在小程序里可搜到。

### 1.3 标签怎么填（这是 AI 好不好用的关键）

AI 导购匹配商品的依据之一就是标签。用户的说法要能被标签接住：

| 用户会说 | 建议标签 |
|---|---|
| 「想吃辣的」 | `辣` |
| 「宿舍囤货」「追剧零食」 | `宿舍必备`、`追剧` |
| 「熬夜续命」 | `提神`、`咖啡因` |
| 「考研用的书」 | `考研` |
| 「有没有笔记」 | `有笔记` |
| 「便宜点的」 | 靠价格字段，不用打标签 |

一件商品建议 3-6 个标签，太多会互相干扰。二手书务必填 `course`（适用课程，如「高等数学（上）」）和 `ISBN`——扫码找书就是靠 ISBN 精确匹配的。

### 1.4 让 AI 帮你写商品文案

在商品列表里对任意商品点「**AI 写文案**」：

1. 选风格（学生口语 / 正式 / 活泼），点「重新生成」
2. 看结果：标题、副标题、卖点、详情、标签
3. 满意就点「**把文案填回商品表单**」，会自动填进编辑弹窗，确认后保存

> 没配大模型 Key 时用的是「模板生成」（标签上会标出来），卖点仍然来自商品真实字段，不会编造。配了 Key 就是模型生成，见第二节。

### 1.5 上架 / 下架 / 改价

- **下架**：商品列表里点「下架」，小程序立刻搜不到（已下单的订单不受影响）
- **改价 / 改库存**：点「编辑」改完保存即可
- **批量看**：用上方的关键词、品类、状态筛选

## 二、把 AI 接上自己的大模型

> **不配也能用**：没 Key 时 AI 走内置规则引擎，「对话 → 调工具 → 商品卡片 → 加购确认」整条链路完全一致，只是话术是模板。适合先做演示，之后随时切换。

### 2.1 三步接上（推荐，全程在后台点）

1. 进「**AI 设置**」页
2. 在「**服务商预设**」里选一家（如 DeepSeek），地址和模型名会自动填好
3. 把从服务商官网申请到的 **API Key** 粘进「API Key」框

然后点「**测试连接**」：

- 显示 `连接成功` → 点「**保存并生效**」，立刻切到真实模型，**不需要重启服务**
- 显示 `连接失败` + 具体原因 → 常见原因见下面 2.3

### 2.2 去哪申请 Key（都兼容 OpenAI 协议，任选一家）

| 服务商 | Base URL | 推荐对话模型 | 备注 |
|---|---|---|---|
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 便宜，中文好，适合这个项目 |
| 阿里云通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 有免费额度；视觉模型 `qwen-vl-plus` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` | 有免费档；视觉模型 `glm-4v-flash` |
| 月之暗面 Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` | 长文本 |
| 本地 Ollama | `http://localhost:11434/v1` | 如 `qwen2.5:7b` | 完全离线，不花钱，需要自己的机器跑 |

**只想先试效果的**：注册 DeepSeek 或智谱，充 10 块钱够用很久（一次对话通常不到 1 分钱）。

### 2.3 配错了会怎样

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `连接失败：接口返回 401` | Key 填错了 / 已过期 | 重新复制 Key，注意不要带空格 |
| `连接失败：接口返回 404` | Base URL 填错 | 对照上表，注意结尾的 `/v1` |
| `模型接口返回 400 ... model not found` | 模型名填错 | 用上表推荐的名字，或去服务商文档查 |
| `连接超时` | 网络不通 | 国内服务器连不上 OpenAI，换国内的；Ollama 确认本地服务已启动 |
| 配好了但 AI 回复还是模板风格 | 保存没生效 / Key 被清空 | 回「AI 设置」看顶部横幅：绿色=真实模型，黄色=本地演示模式 |

### 2.4 三个「可选」字段要不要填

| 字段 | 填了会怎样 | 不填的代价 |
|---|---|---|
| **视觉模型** | 「拍照找同款」能用：用户拍照 → 识图 → 检索商品 | 拍照功能会明确告诉用户「用文字描述或扫码」，**扫码找书依然完全可用** |
| **向量模型** | 语义检索生效：「想吃点解压的」也能搜到辣条 | 退回关键词检索，用户得说「辣条」才搜得到 |
| **超时** | 默认 60 秒 | 保持默认即可 |

填了向量模型之后，还要让技术同学执行一次 `pnpm ai:embed` 把已有商品的知识库补上向量（新加的商品会自动补）。注意：**向量维度必须和建表时一致（默认 1024）**，填了维度不同的模型时系统会自动退回关键词检索并在日志里记一条错误，不会影响其它功能。

### 2.5 不想用后台，改配置文件也行

在项目根目录的 `.env` 里改这三行，然后重启后端：

```bash
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_API_KEY=sk-你的Key
LLM_MODEL=deepseek-chat
```

**优先级：后台设置 > `.env` > 代码默认值。** 所以如果发现改了 `.env` 不生效，去后台「AI 设置」点「恢复默认（.env）」清掉后台保存的配置即可。

### 2.6 成本控制

系统已经内置了这几道闸：

- 单用户 AI 对话限流 30 次/分钟（超了提示「操作太频繁」）
- 用户关掉小程序 / 断网，后端会**立刻停止**正在生成的回答，不再继续烧 token
- 模型调用失败会**自动降级**到本地规则引擎，用户不会看到报错页，也不会重试烧钱
- 一轮对话最多 4 次工具调用，防止模型陷入循环

## 三、其余日常操作

| 要做什么 | 去哪 | 说明 |
|---|---|---|
| 发货 | 订单管理 → 找到「待发货」→ 点「发货」 | 会二次确认 |
| 审核退款 | 售后管理 → 找到「待审核」→ 同意 / 拒绝 | 同意后**自动退款到用户余额**并回滚库存，只点一次，重复点会被后端拦住 |
| 查某笔订单 | 订单管理 → 搜订单号 | |
| 看经营数据 | 数据概览 | 含近 14 天成交趋势、分类销量、支付渠道；「经营快报」是 AI 生成的解读和一条建议 |
| 看 AI 都干了什么 | AI 调用日志 / AI 会话回放 | 每次工具调用的入参出参都有记录，可用于排查「AI 为什么推荐了这个」 |
| 教 AI 回答客服问题 | AI 知识库 → 新增条款 | 改完**立刻生效**，客服助手回答时会带出处引用 |
| 禁用某个账号 | 用户管理 → 点状态开关 | 禁用后对方**立刻**无法继续下单（不需要等登录过期） |
| 给用户退款 / 补偿 | 用户管理 → 调余额 | 支持负数，但不会把余额扣成负数 |

## 四、接手后的第一件事：改密码

默认账号 `admin / admin123` 是公开写在文档里的，**上线前必须改掉**。一行命令搞定：

```bash
pnpm --filter @campus/server admin:password 你的新密码
```

输出「已重置…的登录密码」就成功了，立刻用新密码登录即可。

同时别忘了在服务器上设置一个真实的 `JWT_SECRET`（生产环境用占位密钥会拒绝启动，这是故意的）：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

把输出填到 `.env` 的 `JWT_SECRET=` 后面，重启后端。

## 五、常见问题

**Q：小程序里搜不到刚加的商品？**
A：检查三件事：状态是不是「上架在售」、分类选的是不是当前品类的分类、名字里有没有用户会搜的词。也可以先在后台搜索框搜标题确认商品存在。

**Q：AI 推荐的商品不对？**
A：先去「AI 调用日志」看它到底调了哪个工具、传了什么参数。最常见的原因是商品标签没打全（用户说「想吃辣的」但商品没打 `辣` 标签）。

**Q：图片上传失败？**
A：只支持 png / jpg / webp / gif，单张不超过 5MB（前端会自动压缩，通常不会超）。如果提示「看起来不是有效的图片」，说明文件被改过后缀名。

**Q：怎么把演示数据清干净、正式开业？**
A：正式运营前跑一次（会先把要删的数据备份到 `apps/server/backups/`）：

```bash
pnpm --filter @campus/server data:clear-demo
```

它会清空订单、支付流水、售后单、钱包流水、AI 会话与工具日志、行为埋点，并把商品销量与用户余额归零 —— 后台的「订单总数 / 成交金额」随即变成 0，之后有真实顾客下单才会涨。**商品、分类、用户账号、售后政策知识库都会保留**，商城能正常浏览。

如果连演示/测试时自动创建的账号（每次小程序登录都会建号）也想清掉，让「用户数」一起从 0 开始：

```bash
pnpm --filter @campus/server data:clear-demo --reset-users
```

管理员账号永远保留。想彻底重来（连商品一起回到出厂演示状态）用 `pnpm db:reset`，注意那会**重建所有表并重新灌演示数据**。

**Q：想改商城名字 / 主题色？**
A：小程序在 `apps/miniapp/app.wxss` 与各页面的 `.wxss`，后台在 `apps/admin/src/style.css`。
