# 演示脚本

照着念就能把五个 AI 能力全部演示完，约 10 分钟。

## 零、准备

```bash
pnpm install && cp .env.example .env
pnpm setup          # 建表 + 灌演示数据 + 生成评论摘要
pnpm dev:server     # 终端 A
pnpm dev:admin      # 终端 B
```

**先说一句开场白**（这句很重要，决定了听众的预期）：

> 「这个项目的 AI 不是页面上的一个聊天框。商品、购物车、订单、售后、经营数据，全都是 AI 可以调用的工具 —— 它能真的帮你加购、真的帮你提交售后，而不是只会聊天。」

如果现场没有大模型 Key：**直接演示，不用回避**。打开小程序「我的」页，会显示「本地演示模式（未配置大模型 Key）」。可以这样讲：

> 「没配 Key 时它走内置的规则引擎，工具调用链路和真实模型完全一致，只是话术是模板。这样交付出去不会因为没 Key 就演示不了。」

## 一、对话式导购（小程序 → AI 助手）

**操作**：点底部「AI 助手」→ 点快捷提问「想吃辣的，20 元以内」

**看到**：
1. 先出现黄色小条「正在检索商品」
2. 变成结果摘要「找到 5 件商品，展示前 5 件」
3. 下面是 5 张商品卡片，回复文字说明挑了哪几件

**话术**：

> 「注意上面那条黄色的：这不是装饰，是它真的在调用 `search_products` 工具查数据库。价格和库存都是后端按工具返回值渲染的，模型碰不到价格 —— 这是防幻觉的关键设计。」

**接着操作**：输入「把第一个加购」

**看到**：出现绿色虚线框「加购 卫龙大面筋辣条 106g × 1，合计 ¥3.50」+ 两个按钮「取消 / 确认执行」

**话术**：

> 「这里是最重要的设计：**AI 想写数据时不会直接写**，它先落一条待确认记录，等用户点确认才真正执行。避免出现『聊着聊着被下单』。」

**操作**：点「确认执行」→ 底部购物车角标 +1

## 二、智能客服与售后 RAG

**操作**：AI 助手页顶部切到「客服」→ 输入「退款多久能到账」

**看到**：回复以「根据《退款到账时效》：…」开头

**话术**：

> 「它先检索了知识库再回答，并且**写出了引用的条款名**。知识库在管理后台可以改，改完立刻生效 —— 现场可以演示：新增一条『发票说明』，再问『能开发票吗』，它马上就能答。」

**再试**：「二手书成色怎么定义」「配送费怎么算」「教材回收是什么流程」—— 都会命中对应条款。

## 三、扫码找书（零依赖）

**操作**：AI 助手页点「扫码找书」，扫一本教材背面的 ISBN 条码（或直接在搜索页扫码）

**没书可扫时**：在搜索页输入 `9787040396614` 也能看到效果。

**看到**：「高等数学（第七版）上册」卡片

**话术**：

> 「这是一条**不依赖任何模型**的路径 —— 纯数据库精确匹配。因为找教材是高频刚需，不能因为模型不可用就废掉。工程上该兜住的就得兜住。」

---

## 四、拍照找同款（诚实降级）

**操作**：AI 助手页输入「我拍了张照片想找同款」

**看到**：「抱歉，我这边暂时没法直接看图。你用一句话说说图片里是什么…或者扫书背面的 ISBN 会更快更准。」

**接着操作**：输入「图片里是辣条，帮我找找」

**看到**：正常返回商品卡片

**话术**：

> 「没配视觉模型时它不会假装识图成功，而是明确告诉你它看不了，并给两条替代路径。配了 `LLM_VISION_MODEL` 之后，图片会先被转成结构化标签再去检索，这段代码是同一份。」

## 五、评论摘要与个性化推荐

**操作**：回到首页，指出「为你推荐」里每件商品下面那行绿色小字

**看到**：「本周热销 320 件」「带学长笔记，复习省事」「你偏好重辣，这款辣度够劲」…

**话术**：

> 「推荐不是黑盒。理由按优先级挑：先看画像（口味、预算、课程），再看协同过滤，最后兜底热销。首页右上角那个 `user-cf+profile` 就是当前用的策略，如实标出来。」

**操作**：进一件商品的详情页，往中间滑到「AI 评论摘要」

**看到**：一段总结 + 👍 优点标签 + ⚠️ 槽点标签 + 「适合谁」

**话术**：

> 「摘要有两条生成路径：配了模型就让模型读评论输出 JSON；没配就用模板从真实评分和评论文本里归纳，**不编造**。右下角标注了是 `template` 还是具体模型名。」

## 六、商家侧 AI（管理后台）

**操作**：打开 http://localhost:5173 登录（admin / admin123）→ 数据概览

**看到**：6 项 KPI、成交趋势、分类销量、支付渠道饼图，右下角「AI 经营快报」列出真实数字与一条建议

**话术**：

> 「**这里我刻意没有做 NL2SQL。** 让大模型直接写 SQL 跑在生产库上是不可接受的风险。所以经营分析用的是『指标枚举白名单』：模型只能用自然语言决定问哪个指标、看哪个时间区间，SQL 全是后端预置的。既拿到了对话式分析体验，又不可能被注入。」

**操作**：商品管理 → 找一件商品 → 点「AI 写文案」

**看到**：标题 + 副标题 + 3 条卖点 + 详情 + 标签，右上角标注 `template`

**话术**：

> 「卖点全部来自商品的真实字段（成色、笔记、课程、价格），prompt 里明确禁止编造不存在的卖点。这类『让 AI 写营销文案』的功能最容易胡说，所以约束要写在最前面。」

---

## 七、AI 调用日志与会话回放（答辩杀手锏）

**操作**：管理后台 → AI 调用日志

**看到**：每一次工具调用的工具名、用户、状态、耗时；展开能看到完整入参与返回

**操作**：点任意一行 → 跳到会话回放

**看到**：时间线「用户说了什么 → 调了哪个工具 → 工具返回什么」，下面是写操作确认记录（待确认 / 已确认 / 已取消）

**话术**（这段是全场最有说服力的）：

> 「这是我想强调的最后一件事：**不是『我接了个大模型』，而是『大模型在我的系统里做了哪些事，每一步都可查、可回放』。** 每一次工具调用的入参、返回、耗时都落库了，写操作还有完整的确认记录。」

## 九、答辩可能被问到的问题（附答案）

| 问题 | 回答要点 |
|---|---|
| AI 会不会乱报价？ | 不会：卡片、价格、库存全部由后端按工具返回值渲染，模型只决定调什么工具和说什么话 |
| AI 会不会乱下单？ | 不会：写操作走两阶段，先落 `ai_pending_action`，用户点确认才执行，全程留痕 |
| 没配大模型怎么演示？ | 三层降级，最后一层是内置规则引擎，工具调用链路完全一致，`/api/ai/status` 会如实标注 |
| 推荐算法是什么？ | UserCF 简化版（行为共现找相似用户）+ 画像标签补齐 + 热销兜底，每件都给出可解释理由 |
| 为什么不用 Prisma / MySQL？ | Drizzle + PostgreSQL 是为了让本地零安装（PGlite 内置 pgvector），业务数据和向量同库，不用额外部署向量数据库 |
| 知识库怎么更新？ | 管理后台直接增删改，保存即生效（配了 embedding 模型会同步补向量），不用重启 |
| 怎么加一个新能力？ | 写一个实现 `AiTool` 的类注册进 `ToolRegistry`，前端零改动 |
