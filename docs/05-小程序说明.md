# 原生微信小程序说明

## 一、运行（从零开始）

### 第 1 步：装微信开发者工具

这台机器上目前**只有微信客户端，没有开发者工具**，需要先装：

1. 打开 https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 下载「稳定版 Stable Build → Windows 64」，双击安装（默认下一步即可）
3. 安装完打开，**用微信扫码登录**（不需要注册小程序账号，用游客/测试号就行）

### 第 2 步：导入项目

开发者工具首页 → 「+」新建/导入 → 选「导入项目」：

| 字段 | 填什么 |
|---|---|
| 目录 | `C:\path\to\weixinx\apps\miniapp` |
| AppID | 点「测试号」；或直接保持 `touristappid`（项目里已写好） |
| 后端服务 | 选「不使用云服务」 |

导入后就能看到模拟器里的首页。

### 第 3 步：关掉域名校验（必须）

右上角 **详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」**。

不做这一步，所有请求都会被拦，页面全是「网络异常」。

### 第 4 步：确保后端在跑

§§§bash
cd C:\path\to\weixinx
pnpm dev:server
§§§

后端地址在 `apps/miniapp/config.js` 里，默认 `http://localhost:3100/api`，与默认配置一致，不用改。

### 打开后先看这几个地方

| 位置 | 能看到什么 |
|---|---|
| 首页 | Banner、分类入口、AI 助手入口、带推荐理由的推荐位 |
| 底部「AI 助手」 | **重点**：点快捷提问「想吃辣的，20 元以内」，能看到工具调用过程与商品卡片 |
| 商品详情 | 往下滑有「AI 评论摘要」，底部有「问 AI」按钮 |
| 我的 | 顶部会显示「本地演示模式（未配置大模型 Key）」 |

> **两个说明**：
> 1. 商品图片用的是 `picsum.photos` 在线占位图，**断网时会是灰块**，不影响功能，换成自己的图只需改 seed 数据。
> 2. 登录是静默的：后端没配 `WX_APPID` 时走开发模式，`wx.login` 拿到的 code 直接映射成 openid 自动建号，所以首次进入就有身份，不用手动登录。

### 打不开 / 报错怎么办

| 现象 | 原因 |
|---|---|
| 页面提示「网络异常，请检查后端是否启动」 | 后端没跑，或第 3 步没勾 |
| 真机预览白屏 | 手机访问不到你电脑的 localhost，需要把 `config.js` 的 BASE_URL 改成局域网 IP，并在开发者工具里开启「不校验合法域名」 |
| 控制台报 `request:fail url not in domain list` | 第 3 步没勾 |
| 扫码 / 拍照没反应 | 模拟器不支持摄像头，点真机预览用手机试 |
## 二、登录说明（已改为主动登录）

小程序**第一页是登录页**（`pages/login/index`），必须先选身份登录才能进：

| 身份 | 登录方式 | 登录后 |
|---|---|---|
| **我是买家** | 微信一键登录（`wx.login`），可选填昵称 + 选头像 | 进商城首页，可正常购物、问 AI |
| **我是商家** | 账号 + 密码（默认 `admin` / `admin123`） | 进「商家工作台」：看订单、发货、审核售后；商品编辑与 AI 配置给了电脑端入口 |

**关键改动：不再静默建号。** 以前打开小程序就自动 `wx.login` 建一个「同学3204」，
用户表里全是自动生成的账号，也没有任何登录动作。现在没有 token 就直接跳登录页，
受保护接口根本不会发出去（不会先吃一个 401 再重登）。

买家填的昵称头像会**真的写进用户表**：昵称走 `POST /auth/wx/login` 的入参，
头像因为 `chooseAvatar` 给的是本地临时路径，登录成功后用 token 走 `POST /upload`
换成长期 URL，再 `PATCH /auth/me` 存下来。

### 商家工作台能做什么

- 数据概览：待发货、待审售后、订单总数、成交金额、AI 促成订单数
- 待发货订单列表 → 一键发货（二次确认）
- 待审核售后列表 → 同意退款（自动退款 + 回滚库存）/ 拒绝
- **商品编辑和 AI 配置**：手机端做不了，页面给出电脑端后台地址并支持一键复制

### 后台新增「登录记录」页

管理后台侧栏 → 登录记录：谁在什么时候用哪个账号登录、成功还是失败、来源 IP。
数据来自 `login_log` 表（一直有记录，之前只是没有页面看），接口 `GET /api/admin/login-logs`。


**不需要真实 AppID 也能跑通全流程**：后端未配置 `WX_APPID` 时走开发模式，
`wx.login` 拿到的 code 直接映射成 openid（`dev-<code>`），自动建号并返回 token。
配置了 `WX_APPID` / `WX_SECRET` 后自动切换为真实的 `jscode2session` 换取 openid，代码不用改。

## 四、AI 助手页（核心）

### 流式实现

小程序没有 `EventSource`，只能用 `wx.request({ enableChunked: true })` + `task.onChunkReceived`，
而且回调拿到的是 `ArrayBuffer`。`utils/sse.js` 做了两件事：

1. **增量 UTF-8 解码**：一个汉字可能被切在两个 chunk 里，必须保留不完整字节等下一个 chunk 再拼
2. **SSE 切帧**：一帧也可能跨 chunk，用 `\n\n` 做边界并缓存半截数据

这两件事都有单测覆盖（`tests/miniapp-sse.test.cjs`，用 Node 桩替换 wx API，故意在汉字中间切断数据流）。

基础库过低不支持分块时，自动回退到 `POST /api/ai/chat/sync` 一次性拿结果，界面功能不受影响。

### 界面元素

| 元素 | 说明 |
|---|---|
| 工具过程 | 每次工具调用显示一个黄色小条，完成后替换为结果摘要（例如「找到 5 件商品，展示前 5 件」） |
| 商品卡片 | 由后端 `cards` 事件推送，点击进详情 |
| **写操作确认** | AI 想加购 / 提交售后时出现「取消 / 确认执行」按钮，点确认才真正执行 |
| 消息元信息 | 显示模型名与耗时，降级模式下标注「本地演示模式」 |
| 场景切换 | 导购 / 客服两个场景，客服场景下助手会先查知识库并引用条款 |
| 扫码找书 | 直接调用扫码，把 ISBN 作为一句话发给助手 |

### 页面上下文

商品详情页点「问 AI」会先把 `{ page: 'product', productId }` 写入 storage，
聊天页读取后随请求带上，因此用户说「这个辣不辣」时助手知道「这个」指谁。

## 六、真机 / 开发者工具联调记录

### 首屏请求 401（已修）

第一次在开发者工具里打开时，控制台会出现：

§§§
GET http://localhost:3100/api/cart 401 (Unauthorized)
    at refreshCartBadge (index.js:56)  ← onShow 里查购物车角标
§§§

**原因**：`app.js` 的 `onLaunch` 里发起的登录还没完成，页面 `onShow` 就已经开始请求购物车，
请求不带 token → 401 → 触发「重新登录 + 重试」。功能最终能用，但控制台一片红，还白跑一趟网络。

**修法**：`utils/request.js` 里改成「需要鉴权但还没 token 时，先等登录完成再发请求」，
同时把并发登录合并成同一个 Promise（首屏多个页面同时请求只会 `wx.login` 一次）。
AI 对话页绕过统一封装自己发流式请求，也补了一句 `await api.ensureLogin()`。

回归测试：`tests/miniapp-login-race.test.cjs` —— 断言除登录接口外不存在无 token 的请求，
且购物车只请求一次（如果退回旧实现，会看到 401 后重试，请求数变 2 就会失败）。

## 七、踩坑：`@swc/runtime/_array_with_holes.js is not defined`

在开发者工具里编译时报：

§§§
Error: module '@swc/runtime/_array_with_holes.js' is not defined,
       require args is './_array_with_holes.js'
    at weapp:///pages/mine/index.js:7:24
Component is not found in path "wx://not-found"   ← 连带错误
§§§

**先排除自己的代码**：`apps/miniapp` 下没有任何 `@swc` 字样、所有 `require()` 都是相对路径、
没有 `miniprogram_npm` / `package.json` / `node_modules` —— 这个包是**开发者工具的编译流程注入的**。

两个触发条件：

| 位置 | 值 | 说明 |
|---|---|---|
| `project.config.json` → `setting.enhance` | 原为 `true` | 「增强编译」在新版工具里走 SWC；SWC 压缩器对数组空洞会注入 `_array_with_holes` 助手，但助手模块没被注册 |
| `project.private.config.json` → `libVersion` | 原为 `3.17.3` | 灰度版基础库，会覆盖 `project.config.json` 里的 3.5.0；工具自己也会提示「正在使用灰度中的基础库」 |

**修法**：把 `enhance` 关掉、基础库换回稳定版（3.5.0），然后 **工具 → 清除缓存 → 全部清除**，重新编译。
`minified` 也建议在调试期关掉，否则报错行号对不上源码。

> `project.private.config.json` 在 `.gitignore` 里，属于本机设置，不会影响别人。
