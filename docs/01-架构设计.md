# 架构设计

## 一、整体形态

```
微信小程序（原生，零依赖无构建）  ┐
                                ├─→  NestJS API (:3100/api)  ─→  PostgreSQL + pgvector
Vue3 管理后台（Element Plus）    ┘                                   （本地默认 PGlite）
                                        │
                                        └─→  LLM Provider（任意 OpenAI 兼容接口）
                                              └─ MockProvider（无 Key 降级）
```

## 二、分层约定

| 层 | 位置 | 职责 |
|---|---|---|
| 控制器 | src/modules/*/*.controller.ts | 只做参数校验与响应包装，不写业务 |
| 服务 | src/modules/*/*.service.ts | 业务逻辑；AI 工具调用的落点 |
| 数据 | src/db/schema/*.ts | Drizzle 表定义，唯一数据源 |
| 共享 | packages/shared | 前后端共用的枚举与 Zod 校验规则 |

约定：**AI 工具（tool）不允许绕过 service 直接写库** —— 这样「用户在页面上下单」和「AI 代下单」走的是同一条代码路径，行为一致、可测试。

## 三、双驱动数据库

```
DB_DRIVER=pglite    →  进程内 WASM PostgreSQL 18 + pgvector，零安装，数据落在 .data/pg
DB_DRIVER=postgres  →  docker compose 的 pgvector/pgvector:pg16
```

同一份 Drizzle schema、同一套迁移 SQL（drizzle/0000_*.sql），业务代码不感知差异。
代价是必须让建表顺序正确：**先 CREATE EXTENSION vector，再跑迁移**，所以建表用 src/db/push.ts 而不是 drizzle-kit push。

## 四、AI 运行时的目标形态（P2 落地）

```
用户消息 ─→ 会话装载（历史 + 滚动摘要 + 用户画像 + 页面上下文）
        ─→ LLM 流式调用（带 tools 定义）
        ─→ 模型返回 tool_call
              ├─ 只读工具：直接执行 → 结果回灌模型
              └─ 写操作：落 ai_pending_action，前端弹确认 → 用户确认后才执行
        ─→ 结构化事件流（SSE）：text / tool_start / tool_result / cards / action_confirm
        ─→ 落库：ai_message + ai_tool_call（可观测、可回放）
```

三条硬规则：

1. **商品卡片、价格、库存一律由后端按工具返回值渲染**，模型只负责「调什么工具、说什么话」，从根上防幻觉。
2. **写操作必须二次确认**，且全部记入 ai_pending_action 与 operation_log。
3. **没有 Key 也要能跑**：LLM_API_KEY 为空时切 MockProvider（规则意图解析 + 协同过滤 + 关键词检索），演示链路完整。

## 五、模块规划

| 模块 | 状态 | 说明 |
|---|---|---|
| health | ✅ | 服务 + 数据库 + LLM 配置自检 |
| database | ✅ | 双驱动连接、pgvector 扩展与索引 |
| auth | ✅ | 管理端账号密码登录 + 小程序 code 登录（未配 WX_APPID 走开发模式）+ JWT 守卫与角色守卫 |
| catalog | ✅ | 分类、商品检索（关键词 + jsonb 标签 + 价格/成色/课程过滤）、详情、首页聚合 |
| cart | ✅ | 增删改查、全选、金额与配送费计算，source 区分 miniapp / ai |
| address | ✅ | 收货地址 CRUD 与默认地址 |
| order | ✅ | 结算预览 → 下单 → 模拟支付（含余额扣减）→ 发货 → 收货；管理端分页与数据概览 |
| after-sale | ✅ | 申请、撤销、管理端审核；同意后自动退款入账 + 库存与销量回滚 |
| wallet | ✅ | 余额、模拟充值、流水 |
| ai | ⏳ | 会话、工具注册表、Provider 抽象、SSE 网关（P2） |
| admin | ⏳ | Vue3 管理后台与 AI 调用日志、知识库页面（P4） |

### 已验证的端到端链路（冒烟测试）

管理端登录 → 小程序登录 → 分类/搜索（价格按「元」入参、库内按「分」存储）→ 加地址 → 充值 → 加购（标记 source=ai）→ 结算预览 → 创建订单 → 余额支付（扣减并记流水）→ 管理端发货 → 确认收货 → 申请售后 → 管理端审核退款（退款入账 + 库存回滚）→ 数据概览 KPI。
